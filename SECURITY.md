# Security policy

This v1 release candidate is not published yet. Before publication, the maintainer must enable GitHub private vulnerability reporting and verify it is available on the chosen repository.

Report suspected vulnerabilities using that repository's private **Report a vulnerability** channel. Do not open a public issue with tokens, personal information, transcripts, backups, private URLs or reproduction data from production. If private reporting is unavailable, request a private contact channel without posting exploit details. No unverified personal email address is listed here.

Include affected version, impact, minimal synthetic reproduction and suggested mitigation. Maintainers should acknowledge privately, assess affected releases, coordinate a fix and disclosure, and ask the operator before changing production credentials or data. Supported-version policy will be established with the first release. See docs/security.md.
